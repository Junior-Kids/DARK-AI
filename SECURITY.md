
Security Policy

DARK AI // WormGPT Engine

We take the security of Dark AI seriously. This document explains how to report security vulnerabilities and how security issues are handled.

---

Supported Versions

Security updates are prioritized for the latest maintained version.

Version| Supported
2.8.x| Yes
Below 2.8| No

This support policy may change as the project evolves.

---

Reporting a Vulnerability

If you discover a potential security vulnerability in Dark AI, please report it responsibly.

When reporting a vulnerability, include:

- A clear description of the issue.
- Steps to reproduce the vulnerability.
- Potential security impact.
- Relevant logs or screenshots, if available.
- Suggested mitigation, if known.

Please avoid publicly disclosing exploitable vulnerabilities before the issue has been reviewed and addressed.

Contact: https://github.com/Junior-Kids

---

Security Guidelines

Users and contributors should follow these practices:

1. Never commit API keys, access tokens, passwords, or other sensitive credentials.
2. Store sensitive configuration values in environment variables.
3. Keep Python dependencies updated.
4. Validate external API responses before processing them.
5. Avoid executing AI-generated code without reviewing it.
6. Use the application only in authorized and controlled environments.
7. Do not expose private configuration files in public repositories.

---

AI-Generated Code Disclaimer

Dark AI can generate source code through external or configured language models.

AI-generated code may contain:

- Programming errors.
- Insecure implementations.
- Unexpected behavior.
- Vulnerable dependencies.

Always review and test generated code before executing or deploying it.

---

Scope

This security policy covers vulnerabilities affecting:

- Dark AI application components.
- API request handling.
- Configuration and credential management.
- File handling and export functionality.
- Terminal interaction and input processing.

Third-party services and external AI providers are subject to their own security policies.

---

Responsible Disclosure

We appreciate responsible security research and constructive vulnerability reports.

Please act ethically, respect privacy, and obtain authorization before testing systems or services.
